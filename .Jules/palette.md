## 2024-05-24 - Make AppListItem Entire Row Toggleable
**Learning:** Applying `Modifier.toggleable` to a parent container (like `Row`) instead of just a child element (like `Switch`) significantly increases the touch target size, improving interaction ease. More importantly, it improves accessibility semantics by ensuring screen readers announce the entire row (including context like the app name) as a single switch control.
**Action:** Apply `Modifier.toggleable` or similar parent-level interactive modifiers to list items with toggles instead of relying solely on the child component, while ensuring the child component passes `null` to prevent double firing.
## 2024-05-25 - Add Confirmation Dialog for Destructive Actions\n**Learning:** Implementing a confirmation `AlertDialog` before destructive actions (like deleting a schedule block) significantly prevents accidental data loss and improves user confidence. When managing the dialog state in Compose, localizing the state (e.g., `showDeleteDialog`) within the specific list item composable (`BlockItem`) ensures that each item's deletion flow is handled independently without interfering with others.\n**Action:** Always consider adding confirmation dialogs for actions that permanently delete or alter user data. Ensure that the "confirm" button clearly indicates the destructive nature of the action (e.g., using `MaterialTheme.colorScheme.error`).
## 2026-10-27 - Add Empty States for Better User Guidance
**Learning:** Displaying an empty state with helpful guidance (e.g., "No focus blocks scheduled yet. Tap + to add one.") when there is no user-generated content improves user understanding and engagement. It clearly communicates the current state of the application and provides a call-to-action, preventing confusion that might arise from seeing a blank screen.
**Action:** Always include empty states for lists or screens that depend on user-generated content, ensuring the message is helpful and directs the user on what to do next.
